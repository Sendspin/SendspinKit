## Accepted findings, grouped into chunks

### Chunk 1 — Activation admissibility and role lifecycle (L)

Spec: `messaging.md` "Server → Client: `server/activate`" (activity table, playback-capable
connections, rejection rules, removed-role cleanup); `pairing.md` "Entering and leaving pairing".

- `ActivationAdmissibility.isAllowedSet` must implement the current table: pairing PSK allows
  `[]`, `['pairing']`, `['playback']`¹, `['playback','pairing']`¹; Sentinel allows `[]`,
  `['pairing']`, `['playback']`¹, `['playback','pairing']`¹ (¹ only with unpaired access enabled);
  long-term PSK allows `[]`, `['playback']`.
- `pairing_required` rejection applies to any unpaired session (pairing PSK or Sentinel), not only
  Sentinel.
- Pairing is membership in `activities`, not equality with `['pairing']`:
  `applyInitialPairingActivation`, `handleServerActivate`, pairing-activate counting, and the
  multi-server admission path. Playback is not quiesced when pairing is added (#272).
- `handleServerActivate` must diff old/new versioned roles and, for each removed role (including
  implicit removal and version replacement): metadata/color/controller — discard current state and
  cancel pending scheduled updates immediately, publishing facade-clearing events; player/artwork/
  visualizer — stop remaining output, clear buffers, release temporary effects. Roles that remain
  active at the same version keep their state; in particular `artworkTransfer` must only be reset
  when artwork itself is removed (today any role change discards an in-flight transfer and the next
  part disconnects with `partWithoutTransfer`).

### Chunk 2 — Re-handshake (M), depends on chunk 1

Spec: `connection.md` "Re-handshake".

- Neither hello is re-sent; the first new-key message is `server/activate`, which is a subsequent
  activation on the same connection. `handleRehandshake` must not clear `activeRoles` or role-state
  flags; omitted `active_roles` persists under the new PSK's rules. Remove the repeated-hello reply
  path in `handleServerHello`.
- Connection state (open streams and buffered data, time filter) persists; only session keys change.
  `completedRehandshake` must not clear `artworkTransfer` for an unchanged artwork role.
- Optional hardening (not a MUST on the client): reject non-activation application messages
  received under the new keys before `server/activate`.

### Chunk 3 — Pairing protocol corrections (L; may split 3a wire / 3b lifecycle)

Spec: `pairing.md` "Pairing PSK Flow", "Rounds", "PAKE", "Pairing Window", "Entering and leaving
pairing", "Messages", "Protocol Errors".

3a — wire-level (interop-breaking today):
- Pairing PSK flow: after the pairing activation send `client/pair-init` (with `pairing_index`)
  immediately followed by `client/pair-finalize`; `beginPairingAttempt` sends only finalize.
- CPace `sid` `round` is the round number *within the attempt*, 1 for the first. The Kit feeds the
  persisted device-wide `dynamicRoundCount` (the 20-round budget) into `CPaceSessionIdentifier.make`,
  so any attempt after the first failed round derives a different `sid` from a conformant server.
  Separate attempt-local round numbering from the device-wide emitted-round budget; charge the
  budget only once a code has been emitted.
- `client/pair-init` is sent once per attempt. `handleDynamicServerPairConfirm` sends `pair-retry`
  and then re-sends `pair-init`; after retry the client waits for the server's next
  `server/pair-init`.
- Remove the server-supplied digit audio pack (`DigitAudioPack`, `PairingCodeEmission.digitAudioPack`,
  its validation in `beginDynamicPairingAttempt`/`handleServerPairInit`): the spec now says the
  server supplies none and a speaking client bundles its own audio (#241).

3b — lifecycle:
- Static pairing window is connection-scoped and survives attempts; it closes only on successful
  pairing, the fifth failed server confirmation, connection drop, operator cancellation, or lifetime
  expiry. `sendStaticPairInit` and `clearPairingAttempt` close it today; add the five-failure count.
- A superseding pairing `server/activate` ends the previous attempt's state before the new attempt
  begins (today a second `['pairing']` activation trips `concurrent_attempt` and disconnects).
- Distinguish the post-abort silent-discard interval from out-of-sequence pairing messages, which
  are protocol errors (silent close).

### Chunk 4 — Cleartext `server/error` during init (S), independent

Spec: `messaging.md` "Server → Client: `server/error`"; `connection.md` "Failure Handling".

- `NoiseSessionEstablisher.run` accepts only `server/init` and classifies everything else as
  `HandshakeError.malformed`. Decode an unauthenticated `server/error` (`unsupported_version`,
  `unsupported_suite`, `malformed`) and surface its reason as the handshake failure diagnostic.

### Chunk 5 — Player stream configuration (M)

Spec: `roles/player/v1.md` "Server → Client: `stream/start` player object", "Client → Server:
`client/hello` player@v1 support object", "Measuring timing parameters"; `messaging.md`
"Server → Client: `stream/start`".

- A `stream/start` for a role with an active stream updates configuration without ending the stream
  and clients MUST keep buffered chunks. `handleStreamStart` routes an unchanged format through
  `enqueueStreamStart`, and `AudioEngine.applyStreamStart` bumps `streamGeneration` and discards
  startup/deferred chunks. Distinguish new-stream from active-stream update; characterize the
  startup-phase format-change path (`applyFormatChange` with `shouldClear`) with a test and keep
  old-format buffered audio through it.
- Players MUST advertise FLAC or PCM. `PlayerConfiguration.init` and `effectiveSupportedFormats`
  (after `requireCurrentOutput` filtering) must guarantee the effective hello catalog contains one.
- `bit_depth` is ignored for Opus. `AudioFormatSpec.validate` and equality must not reject or
  distinguish Opus formats by bit depth.
- Arrival-delay samples must use the arrival captured at the application boundary;
  `route(binary:arrival:)` drops `arrival` before `handleAudioChunk`, which takes a fresh clock
  reading.

### Chunk 6 — Non-player roles (M)

Spec: `roles/controller/v1.md` "Client → Server: `client/command` controller object";
`roles/artwork/v1.md` "Server → Client: Artwork (Binary)", "Server → Client: `stream/start` artwork
object"; `roles/visualizer/v1.md` "Visualizer messages", "Server → Client: `stream/start` visualizer
object".

- Controller commands MUST be in `supported_commands` from the latest controller state;
  `SendspinClient.sendCommand` sends unchecked. Validate against connection-owned latest state and
  fail the call (no snapshot yet, or unsupported).
- (Done in chunk 1.) Artwork `stream/end` MUST clear the current image and discard pending images;
  the connection-owned artwork delivery marker (`artworkDeliveryValidity`) is rotated on artwork
  removal, artwork `stream/end`, and changed channel configuration so late deliveries cannot
  restore a cleared image.
- `StreamArtworkChannelConfig` requires `format`/`width`/`height` even for `source: none`, so a
  valid disabled channel fails decoding and the whole `stream/start` is dropped. Decode conditionally.
- Visualizer `stream/start` validation compares `spectrum` unconditionally and rejects an empty
  server type subset; compare spectrum only when the server streams it and accept valid subsets.

## Rejected or downgraded findings

- "Client must enforce new-key inbound sequencing during re-handshake" — the MUST binds the sender;
  kept only as optional hardening in chunk 2.
- "NWWebSocketTransport may deliver fragmented WebSocket frames" — `NWConnection.receiveMessage`
  over the WebSocket protocol delivers reassembled messages; not a gap. A fragmented-message
  transport test is welcome but not required.
- "Server-side buffer-capacity ledger absent" (#288) — defines server accounting; no client
  obligation.
- "Source role formats/fresh starts" (#256/#273) — source is not an advertised Kit role.
- Group-volume rounding (#268), color contrast (#267), group/state publication (#260/#261),
  server-side pairing record (#249), unpairing removes both records (#244) — server obligations.
